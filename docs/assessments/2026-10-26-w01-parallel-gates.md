## Succès observable vs preuve

- **C1 · Pulper fonctionnel sans Redis (13 SP estimés)** — Goal : importer un fichier fictif, en montrer la prévisualisation et confirmer une seule fois sans Redis ni stockage clinique transitoire côté serveur. Nouveau prototype **strictement synthétique/local** : `IAMINA_NO_REDIS=true`, `IAMINA_PULPER_STATELESS_SYNTHETIC=true`, `DEBUG=true`, **pas de `VERCEL` ni `VERCEL_ENV`**. Le guard dans `amina.settings` interdit les configurations incompatibles dès le boot. L'extracteur émet un `preview_token` **AES-256-GCM** avec nonce aléatoire et AAD lié à l'ID patient, UUID batch et version de révocation. Expiration serveur : 3600 s ; texte OCR brut exclu du token ; champ chiffré seulement en mémoire Flutter et renvoyé dans **le corps POST JSON**, jamais l'URL. À confirmation, un digest SHA256 du UUID aléatoire (aucun champ médical) entre dans la table SQL `DocumentConfirmationNonce`, contrainte `UNIQUE`, **même transaction** que la persistance clinique. Échec persist → rollback du nonce ; replay → refus. Déconnexion incrémente la version de révocation et rend le token inutilisable. Privilégier `SECRET_KEY` forte et stable ; rotation invaliderait les tokens. Preuve attendue : nouveau pytest unitaire/DB (A≠B, AAD, altération, expiration, replay, rollback, pas d'OCR brut), migrations Django, schéma OpenAPI, Flutter analyze/tests, W01-B HTTP/PG16.
  
  **Limites explicites :** ce prototype **n'est pas autorisé pour données de santé réelles**, absence de preuve 2 connexions PG simultanées, navigation SSO hébergée, gestion XSS et memory copies, rotation de clé en Vercel, inspection fuite logs/WAL et revue privacy indépendante. La primitive prévient les duplications d'un UUID de batch, elle ne garantit pas exactly-once global après erreur réseau et restitution client. La table de nonce n'a pas de tâche d'épuration planifiée ; à traiter avant données réelles. Aucune activation Vercel.

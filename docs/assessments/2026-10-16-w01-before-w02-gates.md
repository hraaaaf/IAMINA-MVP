## W01-G3 — Durcissement TLS patient-production (17/10/2026)

**Risque identifié par revue externe des standards :** PostgreSQL et Neon expliquent que `sslmode=require` garantit le chiffrement mais pas systématiquement l'identité du serveur, contrairement à `verify-full` avec autorité de certification vérifiée. [Référence PostgreSQL](https://www.postgresql.org/docs/18/libpq-ssl.html) ; [référence Neon](https://neon.com/blog/avoid-mitm-attacks-with-psql-postgres-16).

**Garde renforcée sans déploiement :** rejette aussi les overrides de routage libpq `host`, `hostaddr`, `dbname`, `service`, `servicefile`, `port` en query string (la simple validation du host de l'URL ne suffit pas si une autre option peut rediriger la connexion). Tests adversariaux synthétiques ajoutés.

**Garde proposée sans déploiement :** lorsque `IAMINA_ENV=production`, refuser la cible `VERCEL_ENV=preview`, imposer `sslmode=verify-full` et `sslrootcert=system`. Les connexions sous `IAMINA_ENV=development` conservent la compatibilité avec `sslmode=require` pour les essais synthétiques. Les tests Vercel historiques patient-production utilisent désormais une URL factice incluant ces deux options. La CI prouve uniquement le contrat logique ; vérifier le libpq du build API cible puis la liaison Neon de bout en bout sous environnement test autorisé avant activation production.

# W02 / D10 — Option A, authoritative Web revision (2026-10-28)

**Goal:** implement the smallest safe `Native Bearer → existing Web BFF OIDC proxy → Django PostgreSQL` server metadata revision authority. In an isolated CI PostgreSQL 16 database, prove per-user committed revision, durable reservation, CAS, concurrent writer refusal, crash/resume token, identity revocation, isolation A/B, no cross-user slot reuse and erasure cascade.

**Execution perimeter:** the code is present on an **unmerged** W02 branch. No Vercel deploy, no Neon database touched, no app patient route, no legacy migration. The API requires *both* `VERCEL_ENV=preview` and `IAMINA_W02_REVISION_ANCHOR_ENABLED=true`, and refuses `IAMINA_ENV=production`. No environment flags were changed; default is disabled even on Preview. The Web BFF already forwards IAMINA bearer/requests to protected API Preview with OIDC. We intentionally do **not** enable BFF or production paths.

**Protocol:** GET `/api/v1/w02/vault-revision/state`; POST `/reserve {slot,expected_revision}` stores a one-time pending revision with a random ticket inside a PostgreSQL transaction protected by `select_for_update`; client encrypts to IndexedDB with `durability:strict`; POST `/finalize {slot,revision,ticket,envelope_sha256}` commits monotone floor and digest. The server stores **metadata only**, never a patient record, encryption key, recovery secret or ciphertext. A pending state blocks ordinary reads; after browser crash, the authenticated owner can obtain the pending ticket, verify the local encrypted envelope/revision/digest, and finalize. There is **no automatic abort**: if no durable ciphertext exists the account is deliberately blocked pending an independently audited recovery procedure.

**Security limitations:** server cannot prove that ciphertext was *actually written* to the browser. A malicious authenticated caller could falsely finalize. Storing a digest limits detectable rollback only if a future runtime compares a **canonical digest** for the exact authenticated envelope against the server return, refuses pending, and prevents malicious JavaScript from swapping keys. BFF-bound auth epoch, crash/quota recovery, user key lifecycle, XSS threat, offline UX, and clinical bridge are **not resolved** by this prototype. Option A means **no offline writes without a live trusted server**. Do not mark D10 complete.

**Acceptance:** focused Actions `w02-d10-option-a-revision.yml` must PASS on exact SHA, run `manage.py makemigrations --check`, `migrate`, and isolated PostgreSQL multi-user tests. Tests on SQLite only do not suffice for the `select_for_update` claim. W01 GO, independent audit, Preview GO, real hosted E2E, and UI BEFORE/AFTER remain separate gates.

**Source references:** [Django PostgreSQL row locks](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#select-for-update) and [MDN IndexedDB strict durability hint](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/durability).

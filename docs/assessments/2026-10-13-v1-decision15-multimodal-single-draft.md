# IAMINA V1 decision #15 — One synthetic meal draft across modalities

**Source BEFORE:** [Issue #977](https://github.com/hraaaaf/IAMINA-MVP/issues/977) records code audit of `MealCapturePanel`, `NutritionPortionEditor`, `AddLogSheet` and the Drift log schema prior to changes. Manual catalog selection, user-entered descriptions including dictated text, photo candidates, confirmed candidates and grams already converge into `_selectedMealItemIds`, `_mealNoteController`, `_mealPortionSelections` then a single local insert. Photo proposals stay separate until a tap on Confirm. Actual `AddLogSheet` has one glucose-based `_saveLog`; this is not an independent photo auto-save operation.

**Goal of this independent test-only candidate:** With synthetic fake recognition, retain a pre-existing manually chosen `egg`, allow `whole_grain_bread` only after explicit photo-candidate selection plus confirmation, preserve 75 user-entered grams and French/Arabic note, then prove one in-memory Drift `LogEntry` with matching JSON codecs. Negative fallback/low-confidence photo doesn't alter selection or create any row; unknown food catalog IDs fail closed. Source contract separately guards the single `AddLogSheet` save and same controller for voice text and manual notes. 4 tests, no patient runtime change, no added AI egress.

**Scope limit:** tests compose the actual panel and in-memory DB via a synthetic call to the existing insert schema, **not a full end-to-end rendered Save-button flow**; no real photo, audio or patient data; no dose/carb estimation, PDF, push or background sharing.

**Human gate:** clinical nutrition provenance for natural portions and uncertainty; consent revocation/current verified notice for image/audio egress and retention, explicit confirmation of every proposed ingredient, and visual accessibility. Any UI change must include BEFORE, written mockup, implementation, AFTER same viewports, comparison and score. Until then decision #15 OPEN, no merge/Vercel without permission, CGM #1/#25 last.
